# Memory v2 阶段 2 验收

2026-11-22，Java Memory 与 Java Harness 在独立 JVM 中完成原作者授权、跨会话读取和撤权验收。两个仓库的最终 JAR 同时通过 9 组阶段 2 回放、20 组首版回归和 32 项 Harness 单元测试。另用同一对 JAR 连官方 Gemini，以同一问题核对授权前、授权后、撤销后三次私聊回复。OpenQQ 对端为本地 OneBot 测试渠道，发件人、群号、通知和原因均为合成数据。[验收入口](../../tests/stage2.py)

## 同一通知在三个时点的回复

项目群收到“项目例会改到周六上午十点，地点是雪松厅。”原作者在自己的私聊另外说明了改期原因。另一位用户只问原通知的地点、时间和原因，原作者中途向其私聊授予该通知修订 1 的 `CITE` 权，然后撤销。

| 提问时点 | 真实 Gemini 的渠道回复节选 | 核对依据 |
| --- | --- | --- |
| 授权前 | “没查到例会通知的记录，地点、时间和改期原因都核对不了” | `HISTORY` 输入没有通知的记录 ID |
| 授权后 | “通知写的是周六上午十点，地点在雪松厅，不过里面没有写改期原因。” | 原通知进入交付材料，OneBot 返回发送回执，私聊原因没有进入本轮材料 |
| 撤销后 | “还是没有例会原始通知的记录，所以哪个厅、几点和改期原因都核对不了” | 本轮首个输入收到失效通知，此前回复中的地点与原话均退出本轮上下文 |

这三轮分别保存了规划调用的 Gemini token 计数、实际回复、Worker 读取登记和 OneBot 回执。批次为 `target/acceptance/20261122T154042949008Z/`，逐轮证据在 `gemini-grants.json`。

## 逐项结果

| 验收条件 | 已观察到的结果 |
| --- | --- |
| 旧库迁移 | 带既有原文和回执的 SQLite schema 2 升级到 3，流标识、水位、回执与原文一致。 |
| 确认原作者 | OpenQQ 登录、私聊事件和原消息的账号、发送者匹配后才提交决定。普通服务凭据、控制台身份、他人私聊与错误版本被拒。相同命令重投返回同一持久回执。 |
| 区分只读与引用 | `READ` 可读原文窗口，响应带 `use=READ`。仅有该权时，Worker 的 `CITE` 查询与旧客户端均无法取到正文。增加 `CITE` 后，交付项标明目标会话。 |
| 按受众检索 | 项目群、获准私聊与未获准私聊均通过正式渠道与 Worker 交互。群内可以复述时间和地点。私聊原因没有进入群或其他私聊的模型请求。高相关的不可见材料不挤占授权受众的第一条命中。 |
| 派生项及历史窗口 | 多来源摘要需要全部来源的引用权。撤权后，摘要自身版本虽未变，原文、摘要和先前发出的角色转述在该受众下都无法回读。旧水位和迟到摘要也不能重新发布相应内容。另一目标会话独立保有自己的权利。 |
| 两个 Worker 与进程中断 | Chat Worker 和 Master 均登记过来源。Chat Worker 的更正输入进入 `PREPARED` 时强制中断 Harness，再重启 Memory 和 Harness。两者各自的下轮首个模型请求都收到失效通知，后续输入中无旧地点，期间额外渠道发送次数为 0。 |
| 更正先于读取登记 | 测试代理扣住旧快照，另一轮先处理撤权，再放行迟到快照。交付前复核拒绝过期正文，下一轮用原读取水位补查。 |
| 执行动作前撤权 | 使用正式 Task Worker 与计数采样器。授权仍有效时采样 1 次，在选好工具后撤权，采样 0 次。 |
| 原文编辑与撤回 | 修订 1 的权限在编辑后失效。原作者明确授予修订 2 后才可读到新地点，撤回后再次隐藏。 |
