# Resident v1 迁移到 Memory v2

在旧写入方全部停止后，分别对记忆库和身份库执行 SQLite backup。使用成对的独立快照，运行离线导入器，目标目录须尚未创建。

```sh
java -cp memory.jar neuralcloud.memory.ResidentV1Import memory.sqlite3 identity.sqlite3 new-directory character-id source-instance
```

导入器在一个事务中写入所有修订、变更序号、回执和来源边，逐版校验原始正文 SHA-256，检查外键、数据库完整性和在线索引数量。仅在进程退出码为零，并核对打印的计数、水位和最后变动后，将服务配置指向新目录。每次导入生成新的 v2 流标识。

* 已符合 v2 格式的原 ID 沿用，早期 ID 的双向映射可在 `resident_v1_ids` 查询。原始账本、全部版本的载荷和哈希、生命周期、置顶、来源、身份与旧命令回执分别保存在 `resident_v1_*` 表。
* 关系投影为推断，历史人设作为历史观察。旧库未绑定会话的条目各自隔离。已下线记录在 v2 以撤回状态呈现，既有来源变更继续失效。原会话保持绑定，迁移不会创建跨会话授权。
* 只有原库明确确认且能定位到具体版本的 QQ 身份才进入本人身份查询。原有 QQ 消息须同时满足机器人、发送者、会话字段校验才能进入本人历史。旧来源边缺少版本时，仅当来源只有一个版本才可绑定。
* 旧回执保留原幂等键、版本和提交序号。旧命令保留原哈希，新的 v2 命令占用相同键时会收到内容冲突。失败后使用新的目标目录重试。
